## 1. 设计决策前置（10 条关键取舍）

### D1. 列宽核算必须**显式包含 Card padding + 边框 34px**，且 `scroll.x` ≤ 最窄档可用宽

- **做法**：核算链逐项展开为 `视口 − 15 − 224 − 48 − 32 − 2`（见 §4.2）；只读 `scroll.x = 920`、编辑 `scroll.x = 1008`，二者均按 1280 档（959）与实际取舍分别核算。
- **为什么**：本项目**历史上踩过这个坑**——曾漏算 `Card` 的 `body padding 32` + `边框 2 = 34px`，导致 1440 下常态差 3px、**永远挂着一条用不上的横滚条**（`docs/v1.0-annual-bp-plan-page-design.md` §4.2「v1.0.1 修正说明」完整复盘）。本页核算**从 34px 在内**起算。
- **被否决**：**只写结果数**——数字无法复核，屏宽假设一变（如 Sider 折叠）无法重算。

### D2. 「系统名称」列**不设固定 `width`**，作为唯一弹性列

- **做法**：只读态固定列 `120+170+210+160 = 660`，名称列下界 = `920 − 660 = 260`；编辑态固定列 `110+190+220+150+88 = 758`，名称列下界 = `1008 − 758 = 250`。富余宽（1440 档）**全部落入名称列**。
- **为什么**：① 三个数值列**必须宽度稳定**（`tabular-nums` 右对齐 + 小数点对齐是「最强降噪手段」，`v0.2 §4.4`）；若让 antd 的 `min-width:100%` 等比摊分富余宽，数值列被撑胖、右缘参差；② 名称列是唯一长文本列（主行名 + 副行 `SYS-04 · 门店数字化`），富余宽给它**放大的是有意义的文本区**。
- **被否决**：**5 列全定宽**——富余宽会被 antd 等比摊到 5 列（`v0.6.1 §5` 已记录该行为），削弱数值对齐感。

### D3. 单位**随值**（单价 / 用量单位在单元格内），年度总费用单位**进表头、不入单元格**

- **做法**：单价格 = `¥0.62 元/单`、`¥42 元/千人/月`、`¥2,400,000 / 年`；用量格 = `17,200,567 单/年`、`112,760.5 千人·月/年`、`1.15 份`；年度总费用格 = 纯数字 `722.4`，单位由表头「年度总费用（万元）」承载。
- **为什么**：单价与用量的**单位逐行不同**（见 §6.2 论证），**无法进表头，只能随值**；年度总费用是**全站统一万元口径**，单位进表头即可，单元格再写 = **同一信息说两遍**。与 `OpsPanel`（`BudgetModule.jsx:1202/1208` 单价带单位 + `1220` 表头「年度预估（万元）」）既有做法一致。
- **已裁决**：team-lead 维持本条（§12-C1）。

### D4. 「计费方式」保留，但用**中性 `Tag`（不传 `color`）**，绝不上状态色

- **做法**：`<Tag style={{ marginInlineEnd: 0 }}>{BILLING_MODE_LABEL[billing]}</Tag>`，与 `BillingModule.jsx:740/1107`、`OpsPanel`（`BudgetModule.jsx:1200`）**完全一致**。
- **为什么**：① 跨模块一致性；② 无 `color` = 无假状态语义（`v0.2 §2.3`）；③ `Tag` 浅底把 3–5 字枚举收成离散值，扫读优于裸文本。
- **同源提示（§6「不说两遍」）**：本列语义与「单价单位 / 用量单位」**同源**（均由 `sys.billing` 派生）——若要去冗余，**该删的就是本列**；但用户明确要求 5 列，故**保留且不再强化**（不额外上色 / 加图标）。

### D5. 状态**色只上圆点 / 标签底色**，`warning`（`#C77700`）**绝不用作 ≤13px 正文文字**

- **做法**：主表圆点用 `Badge`（图形，3:1 即可）；页面标签用 `Tag` 且文字取 `*Text` 变体；状态文字本身（「已确认」等）一律 `t3`。详见 §7 / §10。
- **为什么**：`#C77700` 于白底仅 **≈ 3.46:1**（`main.jsx:21` 覆写 `colorWarning`），**未达 AA 正文级 4.5:1**——本项目已踩过该坑。状态色用作**图形 / 填充**合规，用作小字正文不合规。
- **被否决**：把「待业务确认」写成 12px 琥珀色文字；也**不擅自改 `colorWarning` 全站令牌**（须另立专项轮，§10.3）。

### D6. 编辑态**同时放开「单价」与「年度 BU 用量」两列**；`fixed` 行两列**同样可编辑**；其余三列只读

- **做法**：`/new`（S1 编制中）+ Digital 时，**单价**与**年度 BU 用量**两列换 `InputNumber`；`fixed` 行两列**同样可编辑**（其用量口径本轮定义为「折算份数 = 份额 × 增长系数」，单位「**份**」，见 §8.4）；**系统名称 / 计费方式 / 年度总费用**三列只读。
- **为什么**：用户拍板 Q1（**未采纳首版「仅用量」推荐**）——编制期需按 BU 实际议定运维单价，锁死单价会让「整表管理」名不副实（`brief §4.1`）。
- **代价（已在 `brief` 结论前置 4b / §10 差异 17–20 登记，本规范不粉饰）**：与 `DESIGN.md` 110–112 / 49 行「费率预算期锁定、全年不调价」口径冲突（**知情豁免**）；**铁律**：单价编辑只写编制口径 `opsPlans[].items[].rate`，**绝不回写** `SYSTEMS`（`mock.js` 89–98）/ `VOLUME_BASE`（`mock.js` 101–110）。
- **被否决**：首版「仅用量可编辑」——用户未采纳。

### D7. 表格 `size="small"` + **双行行高（44px 档）**

- **做法**：`Table size="small"`；「系统名称」列双行（13px 主 + 11px 副）；行高自然落在 `theme.js:92 tableRowDefault = 44`。
- **为什么**：`v0.2 §2.4.3` 规定「双行字段用 44px」；名称列必须双行，故取 44。
- **被否决**：**36px compact**（`theme.js:91`）——会把副行挤掉。

### D8. **不设「版本」列**、**不设「系统 ID / 所属线」列**；版本号归概览卡、副行归名称列

- **做法**：版本号放**概览卡 / 页头**；`SYS-04 · 门店数字化` 作名称列副行；表底 `summary` 一行承载「共 N 个系统 · 合计 X 万元」。
- **为什么**：整表一个版本 ⇒ 版本号逐行重复 N 遍（`v0.2 §4.4`）；系统 ID 独立列 = 空跑列宽。
- **被否决**：**行内「查看详情」抽屉**——本页每行已是明细。**注**：版本**历史明细**另设 `Drawer`（§3.5），但那是**按版本**展开（每版本一行），非按当前行，不违反本节。

### D9. 编辑态用**独立四段路由 `/new`**，形态照抄 `ProjectBudgetPage`

- **做法**：`#/budget/opsplan/{deptCode}` = **正式版本只读态**；`#/budget/opsplan/{deptCode}/new` = **进行中版本编辑 / 查看态**（对齐 v0.8《项目预算计划》的 `/new`）。`App.jsx` `MODULE_VIEWS.budget` **只注册 `sub='opsplan'`，第四段 `tail='new'` 不注册**（归一 effect 只读 `seg`/`sub`，不读 `tail`，已实读确认）。
- **为什么**：用户拍板 Q3（**未采纳首版「单页切态」推荐**）——进行中版本可分享、可后退，与需求清单页形态对齐。
- **形态对齐**：`/new` 的页头与状态条**照抄** `ProjectBudgetPage.jsx:430–466`（动作按钮组）/ `468–551`（楼层布局）；空态兜底**照抄** `ProjectBudgetPage.jsx:87–102`（`setTimeout(0)` 后 `replace` 回三段，避免同帧竞态）。
- **被否决**：首版「单页内切编辑态」——用户未采纳。
- **保留结论**：编辑态（含 `/new`）需追加「操作」列、宽 88，屏宽紧张时**优先保 1366**（§4.2）。

### D10. 写入路径纪律**逐字复刻**需求清单页（`store.jsx` 289–305 注释）

- **做法**：`保存` 只写 `opsDrafts`；`提交预算` 只改 `opsDrafts.status` + 追加进行中 `planActivity`；**只有业务复核确认**才把 `opsDrafts.items` 写回 `opsPlans[].items`、追加 `opsVersions`（**含完整明细快照**）、删 `opsDrafts`。
- **本规范职责边界**：本规范**只定形态与令牌**；数据模型 / 写入明细属 `brief §6 / §7`（prototype-builder 施工依据）。此处仅登记。

## 3. 楼层规范

- 文本列（系统名称）：左对齐，`ellipsis` + `title`。
- 枚举列（计费方式）：左对齐（`Tag` 左缘对齐）。
- 数值列（单价 / 用量 / 年度总费用）：**右对齐 + `fontVariantNumeric:'tabular-nums'`**（与 `OpsPanel` `BudgetModule.jsx:1205/1217/1224` 一致，保证小数点对齐）。

### 4.4 「单价 / 用量 单位不可进列头」论证（回填 §12-C1）

**结论：单价列与用量列的单位都只能随值、不能进表头。** 依据——两列的三个行单位各不相同：

| 列 | `order` 行 | `member` 行 | `fixed` 行 |
|---|---|---|---|
| 单价 | `元/单` | `元/千人/月` | `元/年` |
| 年度 BU 用量 | `单/年` | `千人·月/年` | `份` |

- 单一表头无法承载「一行一单位」 ⇒ **单位必须落在单元格内**（沿用 `OpsPanel` 1202「单价」+ 1208 单元格带单位的既有做法）。
- **唯一例外**：年度总费用是**全站统一万元口径**，三种计费方式同单位 ⇒ 可进表头「（万元）」、单元格纯数字（沿用 `1220`「年度预估（万元）」+ `1217/1224` 纯数字）。
- ⇒ 因此 §12-C1 的「单位位置」不是偏好问题，而是**由数据形态决定**：金额类列表头带单位，**逐行异单位的两列**随值。

### 5.3 千分位与小数位规则（**三种量纲 + 编辑态两列**）

| 单价 · `member` | 原精度 | **整数或 1 位** | `¥42 元/千人/月`、`¥6.5 元/千人/月` |
| 单价 · `fixed` | `fmtYuan` | **整数元 + 千分位** | `¥2,400,000 / 年` |
| 用量 · `order` | `toLocaleString`（≤1 位） | **至多 1 位小数 + 千分位** | `17,200,567 单/年`、`1,192,327.5 单/年` |
| 用量 · `member` | `toLocaleString`（≤1 位） | **至多 1 位小数 + 千分位** | `112,760.5 千人·月/年`、`11,424 千人·月/年` |
| 用量 · `fixed` | 数值 + 「份」 | **至多 2 位小数**（份额 × 增长系数） | `1.15 份`、`1.04 份` |
| 年度总费用 | `fmtWan` | **1 位小数 + 千分位**（全站万元口径） | `722.4`、`1,234.5` |

- **`fixed` 用量单位是「份」不是「%」**（`brief §4.4` 定稿）：`fixed` 已含增长系数，用百分比会被误读成「份额超 100%」；单元格 `title` 写明口诀（§8.4）。
- **用量小数位（已定稿 = 全量实跑精度事实，非偏好）**：`order` / `member` **至多 1 位小数**、`fixed` **至多 2 位小数**，**均不得取整**。根因可证：`opVolume` 恒为 **50 的倍数**（`calc.js:123` `round(v/50)*50`），`50 × 增长系数`（∈{1.0,1.02,1.04,1.05,1.06,1.09,1.12,1.15}）**至多 1 位小数** ⇒ 用量 = `Σ月度 × 系数` 至多 1 位小数；**`order` 亦含小数**（如 `D-MKT/SYS-02 = 1,192,327.5`）。**取整会破坏恒等式**（`112,760.5 → 112,761` ⇒ `42 × 112,761 = 4,735,962 ≠ 4,735,941`）。
- **浮点噪声处理**：裸浮点可能产生 `5,208,000.000000001`（D-ECOM/SYS-01，9 位小数）—— **落库（`opsDrafts.items[].usage` / `.rate`）与渲染前一律按上述位数 `round`**（`round1 = v => Math.round(v*10)/10`；`round2 = v => Math.round(v*100)/100`）。
- **恒等式精度**：`amount = round(rate × usage)`（取整到**元**），故 `rate × 用量` 与实际「年度总费用」可能在**元级**差 ±0.5 元（如 `0.42 × 17,200,567 = 7,224,238.14 → 7,224,238`）；在「万元、1 位小数」展示粒度下**不可见**，不必专门处理，但**测试不要断言到分**。
- **单价小数位**：`order` 2 位 / `member` 整数或 1 位 / `fixed` 整数元；编辑态同一规则（§8.2 / §8.3）。

## 6. 计费方式的表现形式

### 6.1 结论：**中性 `Tag`（不传 `color`）**

```jsx
<Tag style={{ marginInlineEnd: 0 }}>{BILLING_MODE_LABEL[sys.billing]}</Tag>
// BILLING_MODE_LABEL = { order:'按订单量', member:'按会员规模', fixed:'固定年费' }  （BudgetModule.jsx:76）
```

### 6.2 取舍

| 方案 | 评价 | 结论 |
|---|---|---|
| **`Tag`（无色）** | 与 `BillingModule.jsx:740/1107`、`OpsPanel`（`BudgetModule.jsx:1200`）**完全一致**；浅底把枚举收成离散值；无 `color` = 无假状态语义 | ✅ 采用 |

| `TextTag`（`common.jsx:280`） | 其 `tone` 只有 `ok/warn/bad/info`，**全是状态语义**，此处无状态可映射 | ❌ |
| 纯文本 | 最安静，但丢「离散值」可扫性，且与计费规则 / 账单模块同名列**长相不一致** | ❌ |

### 6.3 「同一信息不说两遍」判定

计费方式的语义由 `sys.billing` 派生，而**单价单位与用量单位也由 `sys.billing` 派生**——同一字段被表达多次：

```
按订单量  ⇔  单价「元/单」    ⇔  用量「单/年」
按会员规模 ⇔  单价「元/千人/月」⇔  用量「千人·月/年」
固定年费  ⇔  单价「元/年」     ⇔  用量「份」
```

- **判定**：本列与「单价单位 / 用量单位」**同源**；若去冗余，**该删的是本列**。
- **处置**：**保留**——① 用户明确要求 5 列（`brief §4.1`）；② 枚举文案是**人类可读标签**，单位符号是**专业简写**，认知任务不同。
- **红线**：保留即**不再强化**（不上色 / 不加图标 / 不加说明）。

### 8.3 校验规则（**与 `brief §4.5` 逐条对齐，不另立一套**）

| 字段 | 规则 | 呈现 |
|---|---|---|
| 单价 `rate` | `> 0`；小数位按计费方式：`order` **2 位**、`member` **整数或 1 位**、`fixed` **整数元**（超位按计费方式舍入） | 违规 → `status="error"` + `title` |
| 年度 BU 用量 `usage` | `order` / `member`：**≥ 0，至多 1 位小数**（**不取整**，见 §5.3 精度事实）；`fixed` 的「份」：**`> 0`**、**至多 2 位小数** | 违规 → `status="error"` + `title` |
| 年度总费用 `amount` | **由 `rate × usage` 推导，不可直接编辑** | 只读展示 |
| 空表（0 行） | **允许保存草稿，禁止提交预算** | 提交 `disabled` + `Tooltip` |
| 删除最后一行 | **允许**（不硬拦截）；删除后若 0 行则按上行门禁 | — |
| 行内不合法 | **不允许提交**：非法行 `status="error"` + 表下提示「N 行未通过校验」，提交按钮 `disabled` | `dangerText` |
| 校验时机 | **行内即时（`onChange`）**，非「提交后报错」 | 提交按钮随校验结果联动禁用 |

- **非数字**：`parser` 清空 → `null` ⇒ 非法，`status="error"` + `title="请输入数值"`。

- **不阻断编辑**：校验失败**不弹 Modal、不锁输入**（沿用 `ProjectBudgetPage.jsx:76–85` 编辑缓冲范式）；「保存草稿」允许带非法值，「提交预算」在存在非法行时 `disabled`。
- **错误提示只用 `Tooltip` / `title` + 红框**，**不在行下再插红字**（避免行高跳动 + 减少单屏 danger 数量，`v0.2 §2.3`）。

### 8.4 `fixed` 行的用量格：**可编辑**（单位「份」）

`fixed` 行的用量本轮定义为「**折算份数 = 份额 × 增长系数**」（`brief §4.4` 定稿），单位「**份**」（如 `1.15 份`），**本身是可议的量**，故：

- **编辑态**：与 `order`/`member` 行同样渲染 `InputNumber`（**不设 `precision`**；`onChange` 内规整至**至多 2 位**小数，`round2` 消浮点噪声；后缀 `<span>份</span>`）；`min` 为 `> 0`（`status="error"` 拦 0 / 负）。
- **只读态**：显示 `1.15 份`（`tabular-nums`，主值色 `t1`）。
- **`title` 口诀（必写）**：`BU 份额 100% × 业务量增长系数 1.04 = 1.04 份`（把「为什么是 1.04 而不是 100%」直接答出，消除 `fixed` 行的最大理解障碍）。
- **为什么可编辑**：用户拍板 Q1/Q2 把 `fixed` 的口径从「系统固有份额」改为「可议的折算份数」——份额 × 增长系数是编制期可调整的估算量（`brief §4.4`），不再属「系统固有属性」。
