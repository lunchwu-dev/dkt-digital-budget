## 1. 设计决策前置（8 条关键取舍）

### D1. 「版本」列置尾 + `fixed:'right'`，不改动用户列序

- **做法**：前 5 列严格按用户原序列出（BP 名称 → 量化目标 → 摘要 → 文档链接 → 修订说明），「版本」作为**第 6 列（系统列）追加在尾部**，并 `fixed:'right'`。
- **为什么**：① 用户逐条需求可按列位 1:1 对应，评审零歧义；② 版本号是 `calc.nextMinorVersion` 生成的**系统产物、非业务内容**，按"用户没提 = 后置"的信息层级追加；③ `fixed:'right'` 保证横向滚动时"我在读哪一版"始终可见（与主表「操作」列同位置）。
- **被否决**：①**版本置首列**——会把 168px 的首屏焦点让给系统字段，而本页信息量最大的是摘要列；②**拆成「版本号」+「提交时间」两列**——宽度预算超（+96+150），必须牺牲摘要列宽，得不偿失（摘要正是最长文本列）。

### D2. 「当前版本」用**文字自身着色 + 字重**表达，不加列 / 色条 / `Tag`

- **做法**：版本列内，当前版本（列表首行）= `c.brand` + `fontWeight:500`；历史版本 = `c.t3` + `fontWeight:400`。
- **为什么**：版本号本身就是那个标量，"当前"只是它的一个档位；用文字着色与字重表达，是**零增量版面的信息承载**，与 `PlanCell`「圆点承载状态、不抢焦点」（`BudgetModule.jsx` 153–231 注释）的设计哲学同源。
- **被否决**：① **`Tag`**——有底色与边框，视觉重量会压过版本号本身（同 §5 AI 来源标记的理由）；② **左侧 3px 色条**——`DESIGN.md`/v0.2 §2.3 明确"整屏 danger 描边只允许卡片级左侧 3px 强调条"，行级色条会与表格分隔线打架；③ **新增「当前/历史」列**——同一信息说两遍，空跑一列。

### D3. **不加概览 `Metric` 卡楼层**

- **做法**：页头之下直接是"列表标题行 + 版本列表"，统计信息降级为列表标题行右侧的**一行 12px `t3` 灰字**：`共 {n} 个版本 · 当前 {V2.1} · 最近更新 {2026-09-22 10:12}`。
- **为什么**：用户明确"页面主体为一个列表"；一排 `Metric` 卡（约 90px 高 + 12px 间距）会把列表推出首屏，与"主体是列表"直接相悖。
- **被否决**：**3–4 张 KPI 卡**——v0.8《项目预算计划》有概览楼层，是因为那一页用户明确要了"当前版本 + 项目总费用"；本页没有此要求，照搬即是过度设计。派生统计（版本数 / 当前版本 / 最近更新）**从版本列表自身派生**，不读 `BP_RECORDS`（避免双真相源）。

### D4. 整表**只读**、无行内操作列、无合计行

- **做法**：`Table` 全表只读（`pagination={false}`、无 `rowSelection`、无行内编辑/删除按钮）；**不设「操作」列**；**不设 `summary` 合计行**。
- **为什么**：① 版本不可变（"每行一个版本"隐含"更新 = 追加新行"），编辑入口本身无意义；② 文档链接列自带外链动作，已覆盖该列唯一的交互；③ 版本之间不是可加总关系（不像项目费用可求和），加"合计"会误导读者以为可累加。
- **被否决**：① **行内「编辑/查看」列**——编辑违反不可变，查看与"整表即全量历史"重复；② **合计行**——语义错误；③ **行内「查看详情」抽屉**——本页每行已是完整快照，再套抽屉是空跑。

### D5. AI 摘要来源标记用 **12px 灰字**（如 `· AI 生成`），不用 `Tag`；摘要**落库为版本快照**

- **做法**：`business` / `ai` 两态在摘要正文后以 12px `t3` 追加 `· 业务填写` / `· AI 生成`；`ai_pending` / `ai_failed` 直接以 12px `t3` 承载状态文案（详见 §5）。
- **为什么**：来源是摘要的**附属属性**，`Tag` 的底色与边框会与摘要正文争夺视觉重心；同理"AI 生成中…"作为过程态，用灰字 + 轻量图标即可，无需 `Tag` 或 `Alert`。
- **被否决**：① **`Tag color="blue"` 标 "AI"**——抢焦点，且会诱导读者以为"AI 生成"是重要状态而非附注；② **每次渲染实时生成摘要**——同一版本不同次打开文本会漂移，"版本记录"稳定性失效（与"合计必须与列内同源"同类错误：同一事实两个来源）。

### D6. 长文本截断：**摘要 2 行、修订说明 1 行**

- **做法**：摘要列 `Typography.Paragraph ellipsis={{ rows: 2 }}`；修订说明列 `ellipsis: true`（1 行）。
- **为什么**：两列都是长文本，若全量展开单行可达 8–10 行、一屏只剩 1–2 个版本，**直接违背"列表"的信息密度诉求**。与 v0.6/v0.6.1 的密度治理同源：先定"一行最多显示多少信息"，再定内容承载方式。
- **被否决**：① **全展开**——列表退化为文档流；② **单元格内「展开/收起」**——列表全只读，为此引入交互成本不值；③ **把长文本移入抽屉**——抽屉已被用户明确否决（本需求正是"独立页面取代右侧浮层"）。

### D7. 浮层 `maskClosable: false` + 无草稿保护

- **做法**：`BpUpdateModal` 的 `maskClosable={false}`；点遮罩不关闭，仅"取消"按钮可关闭。
- **为什么**：用户原文"提交后即更新"= **无草稿态**（v0.9 Q3 已锁定）。既然系统不暂存，**误点遮罩 = 内容全丢**，代价高于"关不掉"的轻微不便，故必须防误关。
- **被否决**：① **`maskClosable` 默认 `true`**——防误关收益 > 方便性；② **引入草稿态**——会把 v0.8《项目预算计划》的草稿能力引入本页，凭空造出第二套生命周期，与 v0.5 定稿的"BP 只有 `已提交/未提交`"2 态冲突。

### D8. 「下钻页壳」用**版式约定**而非**代码抽象**

- **做法**：定义一套可复用的页头版式（`PageHead({title, desc, extra})` + 返回按钮 + 主操作按钮 + 12px `t3` meta 行），配合 `App.jsx` 定位条**自动生效**（§7）。**不抽取共用组件。**
- **为什么**：本轮只落地 `bpplan` 一页；v0.8 的 `project` 页从未落地，**抽象对象不存在**。过早抽象会把未定型的形态固化进公共层，反而制造返工。
- **被否决**：**抽 `DrillPageShell` / `DrillPageHead` 公共组件**——违反 v0.9 §六 N5 的范围约束；且形态统一靠约定即可达成，无需代码耦合。

## 2. 设计令牌映射表

> **总则**：页面内所有颜色 / 圆角**必须**经 `useT()` 取值，**零硬编码色值**；字号 / 字重 / 间距沿用 `docs/v0.2-design-system.md` §2.2 / §2.4 的既有阶梯（**不新增令牌**）。本页不涉及任何金额，因此**不需要新增任何令牌**。

## 3. 楼层规范

页面自上而下 **3 层**，**不加概览卡楼层**（D3）。

```
┌─ 定位条（App.jsx 自动渲染，非本页代码）─ 预算管理 · 编制与消耗 › 年度 BP 计划 › D-RETAIL ─┐
│ 楼层 0 · 页头        PageHead（标题 / 一行口径 / extra：返回 + 主操作）                     │
│ 楼层 0.5 · meta 行   12px t3：业务责任人 X · Digital 对接人 Y · 编制年 FY2027               │
│ 楼层 1 · 列表标题行  BlockTitle「BP 版本记录」+ extra：一行 12px t3 统计                    │
│ 楼层 2 · 版本列表    Card(bg1) > Table size=small，6 列，只读，无合计行                     │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

### 3.1 楼层 0 · 页头（`PageHead`）

| 项 | 规范 |
|---|---|
| 组件 | `PageHead({ title, desc, extra })`（`common.jsx` 13） |
| 标题 `title` | `{部门名} · 年度 BP 计划`，18px / **500** / `t1`（`Title level={4}` 覆盖 fontSize 18） |
| 副说明 `desc` | **一行口径**（≤ 45 字）：`BP 以「一次提交 = 一个版本」记录：最新版本置顶并即时生效，历史版本只读；状态只有「已提交 / 未提交」两种。` 13px / `t2` |
| `extra` | `Flex gap={8} align="center"`：**① 返回按钮** `Button type="text" icon={<ArrowLeftOutlined/>}`，`data-testid="budget-bp-back"`，点击 → `#/budget/annual`；**② 主操作按钮** `Button type="primary" icon={<FileTextOutlined/>}`，文案「修正年度 BP」，`data-testid="budget-bp-update"`，点击 → 打开 `BpUpdateModal` |
| 页根容器 | `data-testid="budget-bp-plan-page"` |
| 角色只读态 | 角色 ≠ 业务部门时，主操作按钮 `disabled` + `Tooltip title="仅业务部门可提交年度 BP"`（C4 口径：Digital 只读），**返回按钮保留** |

### 3.4 楼层 2 · 版本列表（主体）

### 4.2 宽度核算（v1.0.1 修正）

> ⚠ **修正说明（v1.0.1）**：原核算 **漏算了 `Card` 的 `body` padding 32（16×2）+ 边框 2 = 34px**，据此得出 1440 可用宽 1168、`scroll.x` 取 1122。但 1440 下竖向滚动条几乎恒在（页面高≈1433 > 视口高），真实文档宽仅 1425，逐层扣除后表格真实可用宽只有 **1119** → `1122 > 1119` 产生一条**常态化**的 3px 无用横滚条。本版把 `Card` 的 34px 与竖滚条 15px **显式**纳入核算，总列宽收到 **1088**（5 个非关键列各减 4–8px，摘要列不动，截断行数不变）。

| 项 | 值 |
|---|---|
| 固定列宽合计 | `168 + 192 + 124 + 172 + 132 = 788` |
| 摘要列（`flex`）下限 | `300` |
| **表格最小宽（`scroll.x`）** | `788 + 300 = **1088**` |

**核算 1 · 1440 视口（Sider 展开 224）**
```
可用宽 = 1440 − 15(竖向滚动条) = 1425
       − 224(Sider 展开) − 48(页左右 padding) = 1153
       − 34(Card body padding 16×2 + 边框 2) = 1119   ← 表格真实可用宽
表格最小宽 1088 ≤ 1119  →  不溢出 ✅（无内部横滚）
富余 31px 由浏览器在 6 列间摊分（摘要列实得最大）
```

**核算 2 · 1280 视口（Sider 展开 224）**
```
可用宽 = 1280 − 15 − 224 − 48 = 993；− 34(Card) = 959
表格最小宽 1088 > 959  →  溢出 129px  →  出现内部横滚（由 scroll.x=1088 兜住）
「版本」列 fixed:'right' 常驻可见 ✅（横滚时行标识不丢失）
```

**核算 3（补充）· 1366 视口（Sider 展开 224）**：可用 `1366−15−224−48=1079`，再减 Card 34 = `1045`，`1088 > 1045` 溢出 43px，出现内部横滚。**结论**：1366 是内部常见分辨率，此档**保留内部横滚 + `fixed:'right'` 保护版本列**（版本列常驻可达即可）；Sider 折叠为 64 后，1366 可用 `1366−15−64−48−34=1205 ≥ 1088`，**完全无横滚**。

**Sider 折叠态**：折叠宽 64（`theme.js siderCollapsedWidth`），1440 可用 `1440−15−64−48−34=1279`、1366 可用 `1205`、1280 可用 `1119`，**三者均 ≥ 1088，全部无横滚**。

### 9.1 背景定义

本页所有文字均落在三种底上：`bg1`（Card / 浮层表面，`#FFFFFF`）、`bg3`（`Hint` 底 ≈ `#F5F7FA`）、以及品牌浅底 `brandBg`（仅 hover 瞬间，非常态阅读面）。下表以 `#FFFFFF` 为主要背景核算（`brandBg` hover 非常态，不参与正文可读性判定）。

### 9.2 文字着色项核算

| 位置 | 前景令牌 | 前景实测（Ant 派生） | 背景 | 对比度 | 是否达 AA 4.5:1 |
|---|---|---|---|---|---|
| 当前版本文字 | `brand` | `#005BAA`（`colorPrimary`） | `#FFFFFF` | **≈ 6.83:1** | ✅ 通过 |
| 当前版本文字 | `brand` | `#005BAA` | `bg3` ≈ `#F5F7FA` | **≈ 6.37:1** | ✅ 通过 |
| 文档链接文字 | `brand` | `#005BAA` | `#FFFFFF` | **≈ 6.83:1** | ✅ 通过 |
| 修订说明正文 | `t2` | `colorTextSecondary` = `rgba(0,0,0,.65)` → `#595959` | `#FFFFFF` | **≈ 7.00:1** | ✅ 通过 |
| 主文本（名称/目标/摘要正文） | `t1` | `colorText` = `rgba(0,0,0,.88)` → `#1F1F1F` | `#FFFFFF` | **≈ 17.4:1** | ✅ 通过 |
| **版本列次行 / 来源标记 / 统计行 / 空态文案 / `Hint` 正文** | `t3` | `colorTextTertiary` = `rgba(0,0,0,.45)` → **`#8C8C8C`** | `#FFFFFF` | **≈ 3.36:1** | ❌ **不通过**（正文级） |

### 9.3 结论与处理建议（`t3` 争议项）

**发现（必须显式登记，不可默默放过）**：

- `useT().t3` = `token.colorTextTertiary`，其**运行值**为 Ant 种子派生的 `rgba(0,0,0,0.45)`（`main.jsx` **未覆写** `colorTextTertiary`），叠加在 `#FFFFFF` 上等效 `#8C8C8C` ⇒ **≈ 3.36:1，不达 AA 正文级 4.5:1**。
- 注意：`docs/v0.2-design-system.md` §2.1.2 / 附录 A.4 把 `--dkt-t3` 记为 **`#6B7280`**（于白底 ≈ **4.83:1**，**刚好通过**）。**该 hex 是"基准参考值"而非运行时值**——文档原话为"值由 Ant 派生，此处给基准"。**两套口径给出相反结论**，这是本节的核心风险点。

**处理建议（三选一，推荐 B）**：

| 方案 | 做法 | 评价 |
|---|---|---|
| A 维持 `t3` 不动 | 承认 12px 灰字为"可忽略的辅助信息"，沿用全站既有基线 | ⚠ 与 WCAG AA 有出入；但 `t3` 已在 `PlanCell` 次行、单位"万元"、空态等处**全站铺开**，本页单独换色会造成同页灰度不齐 |
| **B（推荐）分类取值** | ① **纯元信息**（版本列次行 `at · owner`、统计行、单位）→ **保持 `t3`**（属"辅助/可跳过"信息，且改动会破坏与主表的一致性）；② **承载语义、必须可读**的灰字（**AI 来源标记 `· AI 生成`、空态引导文案**）→ 改用 **`c.t2`**（≈ 7.0:1，✅ AA） | 在不改全站 token、不破坏灰阶体系的前提下，把"必须读得清"的少数文字提到 AA |
| C 提全局需求 | 立项"全站文字对比度校准"轮，统一 `t3` 取值（如锁 `#6B7280`） | 超出本轮范围（N9：本轮只新增本页文档） |

> **不擅自改全站品牌色 / 令牌**：`t3`、`brand` 均为全站级 token，**本页不得就地覆写**。方案 B 仅把**本页两处**（来源标记、空态文案）改用既有的 `c.t2`——两者都是既有令牌，**不新增、不修改任何 token**；其余 `t3` 用法照旧。若采纳方案 B，请在评审记录中标注"本页对 `t3` 有 2 处 AA 例外，后续全站校准轮统一"。

**其他**：

- 本页**无金额 / 无消耗率** ⇒ 文档要求的"消耗率类着色"自查项**本页不适用**（该着色出现在《预算消耗》页）。
- `Badge` 圆点（仅主表入口格）为非文字图形，`brand` 于白底 6.83:1 ≥ 3:1（图形元素 AA 建议值），✅。
- `ai_pending` 的 `LoadingOutlined` 为非语义图形，`t3` 于白底 3.36:1 ≥ 3:1，✅（图形豁免正文 4.5 要求）。
- 焦点可见性：返回按钮、主操作按钮、文档链接、`Table` 行（若可聚焦）须保留 Ant 默认 `focus-visible` 描边（`borderStrong` / `brandBorder`），**不得 `outline:none`**。
