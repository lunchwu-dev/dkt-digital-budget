# v0.5.1 · 年度预算计划主表信息密度精简

> 变更范围：仅「预算管理 › 年度预算计划」主表三个编制项单元格的**呈现内容**。
> 编制口径（v0.5 状态机与版本规则）、数据结构、动作按钮、下钻抽屉一律不变。

## 1. 用户要求

> 年度BP列显示：版本号，状态，其余信息不用了
> 项目预算列：总费用，项目条数，状态，其他信息不用了
> 系统运维预算：系统数量，总费用，状态，其他信息不用了

## 2. 改了什么

### 2.1 单元格版式（核心）

`PlanCell` 从「标签 + 主文案 / 副文案（时间戳旁注）」两行结构，改为**固定两条信息以内**：

```
第一行：[状态 Tag]  主数值
第二行：(可选)      次数值
```

- 移除了原第二行常驻旁注（`最近更新 2026-09-22 · 点击查看 ›` 这类时间戳文案）。
- `main` 由内联 `<Text>` 改为组件内统一渲染（13px / 500 / `tabular-nums`），
  让三个数值列的数字**纵向对齐**。
- 单元格 `aria-label` 改为 `状态 + 主数值 + 次数值` 拼接，不再依赖已删除的旁注。

### 2.2 三个编制项的最终呈现

| 编制项 | 状态 | 第一行 | 第二行 |
|---|---|---|---|
| ① 年度 BP | 已提交 / 未提交 | 版本号（`V2.1`）；未提交为 `—` | 无 |
| ② 需求清单及费用预估 | 已确认 | `304.8 万元` | `4 条` |
| | 待评估费用 | `待核定` | `3 条` |
| | 未提交 | `—` | 无 |
| ③ 系统运维预算 | 已确认 / 待业务确认 / 编制中 | `268.4 万元` | `N 个系统` |
| | 未启动（Digital 未出具） | `待出具` | `N 个系统` |

两处刻意的取舍：

1. **②「待评估费用」不给金额，显示 `待核定`**。该状态下 Digital 尚未逐条核定，
   若把业务预估值当「总费用」展示会误导；明细仍可在抽屉的清单表里看到
   「业务预估（万元）」列。
2. **③ 未出具时费用位显示 `待出具`，但系统数量照常显示**。
   `opsSystemCount` 是计费模型推导出的**覆盖范围**（业务事实，始终可算），
   而「总费用」必须等 Digital 出具（`opsPlan.issueDate` 非空）才成立。

### 2.3 被移出的信息去哪了

| 信息 | 新位置 |
|---|---|
| BP 提交时间、文档链接 / 附件份数 | 单元格 `title` 悬停提示 + BP 抽屉 |
| 需求清单版本号、提交 / 确认时间、变更说明 | 需求清单抽屉的**版本记录表**（`budget-demand-versions`） |
| 运维版本号、出具日、业务确认日 | 单元格 `title` 悬停提示 + 运维抽屉 |
| 需求逐条金额 | 需求清单抽屉的清单表（`budget-demand-table`） |

`title` 提示是零版面成本的兜底，避免「精简」退化成「信息丢失」。若不需要，
删掉三处 `title={...}` 即可。

### 2.4 列宽与合计行

- 列宽：BP `210 → 160`，需求清单 `280 → 210`，运维 `210 → 190`；
  整表 `scroll.x: 1180 → 1010`。
- ③ 运维列**取消 `align: 'right'`**：三列状态 Tag 现在纵向成一条线，扫描更顺；
  合计行同步取消右对齐。
- 合计行的运维汇总由「仅总费用」改为「`N 个系统 · X 万元`」。
  ⚠️ 这里的 `N` 用 `Set` 对系统 id **去重**：同一系统（如数仓 `SYS-07`）被多个部门共用，
  逐行相加会重复计数，得到无意义的数字。
