## 0. 一句话结论

把主表「① 年度 BP」格的下钻从**右侧浮层**改为**独立页面** `#/budget/bpplan/{deptCode}`：页面主体为该部门 FY2027 的全部 BP **版本列表**（每行一个版本，6 列），页内唯一入口「**修正年度 BP**」弹出专用浮层 `BpUpdateModal`，提交即追加一个版本（版本号由 `calc.nextMinorVersion` 生成）。内容字段整体从 `BP_RECORDS` 下移 `BP_VERSIONS`，**版本列表成为唯一真相源**。

## 3. 新增的共享派生工具（文案同源）

为避免「文档形式文案」「摘要来源文案」在**主表 title / 综合视图卡片 / 新页面列表**三处手写漂移，统一收敛到 `calc.js`：

| 函数 | 语义 |
|---|---|
| `bpDocsOf(v)` | 返回 `(v && v.docs) \|\| []`。 |
| `bpDocFormLabel(v)` | 无文档 → `'未提供文档'`；全部 `link` → `'文档链接'`；否则 → `` `${n} 份附件` ``。 |
| `bpSummaryStateOf(v)` | 返回 `{ text, source, sourceLabel, pending, failed }`，映射四态 + `null` 兜底（见下）。 |

`bpSummaryStateOf` 映射规则：

| `summarySource` | `text` | `sourceLabel` | 列内呈现 |
|---|---|---|---|
| `business` | `v.summary` | `业务填写` | 正文 13px `t1` + 12px `t2` 后缀「· 业务填写」 |
| `ai` | `v.summary` | `AI 生成` | 正文 13px `t1` + 12px `t2` 后缀「· AI 生成」 |
| `ai_pending` | `AI 生成中…` | `null`（`pending:true`） | 12px `t3` + `LoadingOutlined` |
| `ai_failed` | `AI 生成失败 · 可在「修正年度 BP」中补充` | `null`（`failed:true`） | 12px `t2` |
| 其它 / `null` | `—` | `null` | 13px `t3` 兜底 |

> 来源标记一律**灰字不用 `Tag`**（设计规范 D5）；`ai_failed` 用 `t2` 而非 `danger`（§9 方案 B：避免单屏告警过载，同时保证「必须可读」的引导文案达 WCAG AA）。

## 4. 提交链路说明

```
业务点击「修正年度 BP」
  └─▶ BpUpdateModal 打开（无历史 → 首版；有历史 → 标题预告 V{next}）
        └─▶ BpUpdateForm 校验（validateFields：名称/目标/≥1 条文档/修订说明）
              └─▶ Form.onFinish(values)
                    └─▶ planAction({ deptCode, fy:2027, stage:'BP', action:'提交',
                                     note: changeNote,
                                     payload:{ name, goals, summary, docs, changeNote },
                                     actor: bpOwner, role:'业务部门' })
                          ├─▶ store：history = bpVersions(dept, fy)
                          │        nextVersion = calc.nextMinorVersion(history)   ← 版本号唯一来源
                          │        bpVersions = [ 新快照, ...旧 ]                  ← 只写这一处
                          │        activity.version = nextVersion                 ← 留痕
                          │        若摘要为空 → 登记 aiBackfill 任务
                          ├─▶ msgApi.success(`BP 已更新为 ${nextVersion}`) → 关闭浮层
                          └─▶ setData 提交后：
                                · 列表首行出现新版本（V2.2…），主表「① 年度 BP」格版本号同步刷新
                                · 若 ai_pending：1200ms 后 setTimeout 内 setData 按 id 单向回填 summary=模板文本、summarySource='ai'
```

**关键约束落地**：
- 一次提交 = 追加一个版本（非覆盖），历史版本只读、不可删；本轮不提供回滚。
- 每次提交写一条 `planActivity`（`stage='BP'`、`action='提交'`、`version=新版本号`）。
- 入口收敛：主表 BP 格、主表「操作」列「更新」、综合视图 BP 卡片三处**全部跳新页面**；`PlanActionModal` 不再承接 BP（仅 DEMAND/OPS 使用）。

**AI 摘要模板文本（不编造任何具体数字）**：
```
`${name}：围绕「${goals 首行}」展开，配套 ${docs.length} 份文档；聚焦年度目标落地与 Digital 资源匹配。`
```

**证据**：Chrome 实测 `.ant-table-content` `clientWidth === scrollWidth === 1122` → antd `fixed:'right'` 失效；外层 `Watermark` 容器自带 `overflow:hidden` 把溢出部分直接裁掉。
**根因**：antd `Layout` 为 flexbox，内部子项默认 `min-width:auto`，视口变窄时子项不收缩到内容宽以下，溢出无法下移到表格内部的横向滚动容器。
**修复**（`src/App.jsx`）：
- 内层 `<Layout style={{ minWidth: 0 }}>`（附 4 行注释说明收缩链）。
- `<Content style={{ padding: '16px 24px 32px', minWidth: 0 }}>`。
- 列宽与 `scroll.x` **未改**（仍 1122），「收窄列宽规避 1366 横滚」的选项**未采纳**。

**验收实测（真实 Chrome，非 jsdom）**：

| 视口 | 页面横向溢出 | `.ant-table-content` clientW / scrollW | 内部横滚 | 「版本」列 right | 完全可见 |
|---|---|---|---|---|---|
| 1440×1400 | 无（bodyScrollW 1425 = docClientW 1425） | 1119 / 1122 | 是 | 1384 ≤ 1440 | 是 |
| 1440×900 | 无（1425 = 1425） | 1119 / 1122 | 是 | 1384 ≤ 1440 | 是 |
| 1366×900 | 无（1351 = 1351） | 1045 / 1122 | 是 | 1310 ≤ 1366 | 是 |
| 1280×900 | 无（1265 = 1265） | 959 / 1122 | 是 | 1224 ≤ 1280 | 是 |

> 说明：三视口下 `body.scrollWidth === documentElement.clientWidth`，即**页面级横向溢出为 0**（「1440 无横向滚动」达成）。1440 下 `docClientW=1425` 的 15px 缺口来自**竖向**滚动条（页面内容高 ≈1433 > 视口高），非横向；此时 `.ant-table-content` 因这 15px 出现 3px 的内部横滚 —— 属表格内部滚动条（设计预期），非页面横向滚动。

### 8.2 ② P1 · 同分钟两次提交，新版本不置顶

**证据**：row0=`V2.2`、row1=`V2.3`；主表「① 年度 BP」随之取到错误版本。
**根因**：`bpVersionsOf` 比较器 `(a,b)=>(a.at<b.at?1:-1)` 对相等返回 `-1`（非 `0`），不是合法全序；`at` 仅到分钟。
**修复**（`src/domain/calc.js` `bpVersionsOf`）：合法全序 + 显式 tie-breaker（版本 id 末段序号降序），不依赖引擎稳定排序；**未改 `at` 格式**（`store.jsx` 的 `slice(0,5)` 保持不变）。
```js
const seqOf = (id) => { const n = Number(String(id || '').split('-').pop()); return Number.isNaN(n) ? 0 : n; };
.sort((a, b) => (a.at !== b.at ? (a.at < b.at ? 1 : -1) : seqOf(b.id) - seqOf(a.id)))
```
**验收**：
- 单元级（同分钟三连提合成数据）→ 顺序 `V2.3, V2.0, V1.0`（最新置顶）；`cmp(x,x)===0`（合法比较器）。
- 冒烟级（真实两次提交，经浮层点击）→ 首行 = `V2.3` + 新名称；版本总行数 = 5（3 存量 + 2 新增）；主表 `budget-annual-cell-bp-D-RETAIL` 含 `V2.3`。
