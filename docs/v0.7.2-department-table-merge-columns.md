# v0.7.2 · 部门预算消耗表：预算与消耗并为单列

> 变更范围：仅「预算管理 › 预算消耗 › 楼层二《部门预算消耗情况》」的列结构。
> 楼层一三张卡、`consumptionBreakdown` 口径、`store.adjustProjectBudget`、「调整预算计划」抽屉分支一律未动。

## 1. 用户要求

> 预算和消耗在同一列，展示总预算金额，消耗百分比就好，不用 分开两列

## 2. 改前 / 改后

**改前（v0.7.1）**：三个维度各拆两子列 —— `预算（万元）` 108px + `消耗（万元）` 120px，
分组表头两行，一行 8 个叶子列、合计宽度 958px。

**改后（v0.7.2）**：三个维度**各占一列**，单行表头 5 格。

```
业务部门    │ 整体预算及消耗 │ 项目预算及消耗 │ 运维预算及消耗 │ 操作
────────────┼────────────────┼────────────────┼────────────────┼──────
零售运营      │      1,220.0 万元 │       436.3 万元 │       783.7 万元 │ 查账
D-RETAIL     │      已消耗 54.7% │      已消耗 53.6% │      已消耗 55.3% │ 调整预算计划
```

- 上行 = **总预算金额**（14px/500 + `万元` 11px 小字后缀，沿用 v0.6 的单位后缀约定）；
- 下行 = **已消耗百分比**（13px/600，按该维度自身档位着色）；
- 合计行同构（字号升一档、字重 600），三格的率同样着色。

理由很直白：同一维度的「预算多少」和「吃掉多少」本来就要连起来读，
中间隔着一列 108px 的空白没有理由 —— 眼睛要跨过它去对两个数。

## 3. 消耗金额不再单列（以及它去了哪）

格内只剩「总预算 + 消耗率」两个数。**消耗金额 = 总预算 × 消耗率**，两个可见数乘一下就有，
不必占一列。为了让「精简」不退化成「信息丢失」，被移出版面的量全部进单元格 `title` 原生提示
（沿用 v0.5.1 的做法，零版面成本）：

```
零售运营 · 整体
  title = 预算 1,220.0 万元 · 已消耗 667.1 万元 · 已核销 568.8 + 已承诺 98.3
          （BRD 签收锁价、尚未出账） · 可用 552.9 万元

零售运营 · 运维
  title = 预算 783.7 万元 · 已消耗 433.3 万元 · 已核销 433.3
          （运维按月计费，无「承诺」中间态） · 可用 350.5 万元
```

运维侧单独成句，**不写进「已核销 + 已承诺」的加法里** —— 运维没有承诺中间态，
混进同一个句式会让人以为那里有个 0.0 的承诺数。

同时被移除的还有原预算子列的第二行脚注（整体的 `总包`、项目 / 运维的 `占 xx.x%`）：
列头已经写明维度名，占比可由合计行除得。

## 4. 列宽

| 列 | v0.7 | v0.7.1 | v0.7.2 | 依据（格内实际最长内容实测） |
|---|---:|---:|---:|---|
| 业务部门 | 116 | 116 | 116 | 不动 |
| 三个维度（各） | 108 + 156 | 108 + 120 | **132** | 最长内容 = 表头「整体预算及消耗」7 字 ≈98px；次长 = `已消耗 294.8%` ≈78px。132 含 16px 内边距后余约 18px |
| 状态 | 120 | — | — | v0.7.1 已删 |
| 操作 | 158 | 158 | 158 | 不动 |
| **合计** | **1186** | **958** | **670** | 累计减去 **516px（−43.5%）** |

`scroll.x: 958 → 670`。在 1280 屏（内容区约 976px）下三列会被 antd 等比撑开约 46% ——
这是既定的「铺满容器而非锁定列宽」策略（v0.6.1 §6 的取舍），数字右对齐贴在各列右缘，
不会看起来「没做完」。
