> 编制口径、状态机、数据结构、单元格信息层级（v0.6 的两级版式）、动作按钮、抽屉内容一律不变。

## 1. 用户要求

> 调整列宽，提升屏效

## 2. 旧列宽的问题

| 问题 | 具体表现 |
|---|---|
| **总宽虚高** | `scroll.x = 965`，但六列内容实际最多只需 858px。多出的 107px 在 1280/1366 笔记本（叠上 125% 显示缩放）下会直接触发横向滚动 |
| **列宽与内容脱节** | ① 年度 BP 列宽 140px，格内只有一个 `V2.1`（约 38px）+ 一行 `● 已提交`（约 60px）—— 一半是空气 |
| **行高偏高** | `size="middle"`（上下 padding 12px）+ `PlanCell` 自身 padding 4px + 行间距 4px → 单元格行高约 **74px**，8 行占 592px，一屏看不全 |

## 3. 改后的列宽规划

| 列 | 旧 | 新 | 依据（按格内实际最长内容实测） |
|---|---:|---:|---|
| 业务部门 | 168 | **170** | 第二行 `D-RETAIL · Digital 郑亦凡`（11px）约 146px + 单元格水平 padding 16px |
| ① 年度 BP | 140 | **112** | 主数值 `V2.1` ≈ 38px；状态行 `● 已提交` ≈ 60px |
| ② 项目预算 | 185 | **164** | 主数值 `304.8 万元` ≈ 82px；状态行 `● 已确认 · 4 条需求` ≈ 130px（最长内容） |
| ③ 系统运维预算 | 190 | **168** | 表头「③ 系统运维预算」7 字 ≈ 98px 反而比格内内容更宽，以表头为准 |
| 编制完整度 | 150 | **128** | 进度条 + `2/3`，进度条已改弹性（见 §5） |
| 操作 | 132 | **116** | 两个 `type="link" size="small"` 按钮「查看」「更新」约 90px |
| **合计** | **965** | **858** | 横向最小宽度减少 **107px** |

`scroll.x: 965 → 858`。在 1366×768 笔记本（浏览器可用宽约 1062px）下由「贴边」变为留有余量；
在 1280 屏（可用约 976px）下不再触发横向滚动。

## 4. 行高与密度

| 项 | 旧 | 新 |
|---|---|---|
| Table `size` | `middle`（单元格上下 padding 12px） | `small`（8px） |
| `PlanCell` 内边距 | `4px 8px` | `2px 6px` |
| `PlanCell` 行间距（主数值行 ↔ 状态行） | `gap: 4` | `gap: 2` |
| **单元格行高** | **约 74px** | **约 60px** |

8 个 BU 的表格体由约 592px 降到约 480px，一屏多显示约 2 行。
`marginLeft` 同步从 `-8` 改为 `-6`，与新的左 padding 对齐（hover 态左边框不会溢出单元格被裁切）。

## 5. 一个让"被撑开"也有意义的小改动

antd 的表格在有 `scroll.x` 时会设 `min-width: 100%` —— 容器比 858 宽时表格会铺满，
多余宽度按列宽等比分配。这是 antd 的既定行为，宽屏下列会变胖。

本次没有去禁用这个行为（**取舍见 §6**），但做了一处配合：**「编制完整度」列的进度条改吃弹性宽度**
（`flex: 1 1 auto; minWidth: 40`，原来是写死的 `width: 62`）。
这样列被撑开时，变长的是进度条本身，而不是留出一片空白 —— 放大变成有意义的。

## 6. 明确没做的事（取舍说明）

**没有锁定列宽不让它随屏幕放大。** 原因：

- antd Table 的 `min-width: 100%` 是组件默认行为，要覆盖得加全局 CSS 打补丁；
- 覆盖后表格会在宽屏上锁定 858px、右侧留一大片空白（1440 屏约 278px），观感更像"表格没做完"；
- 与之相对，等比铺满虽然会放大列宽，但至少占满了容器。

如果你要的是**列宽绝对稳定**（大屏下也不放大），我可以加一个类把表格锁在 858px 并居中 ——
一行 CSS 的事，说一声就改。
