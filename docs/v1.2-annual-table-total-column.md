# v1.2 · 年度预算计划主表：两列减法 + 「总预算费用」列

## 1. 需求

用户口头需求（2026-10-02）：

1. 「编制完成度」列不需要了；「操作」列也不需要了。
2. 加一列「总预算费用」，展示 **项目预算 + 系统运维预算** 的总和。

## 2. 两处减法的依据

| 移除项 | 依据 |
|---|---|
| 编制完整度列 | `done/3` 是 ①②③ 三格状态圆点的**派生量**（同源重复）——用户逐格已能看出齐备与否，整列「进度条 + n/3」是把同一信息说第二遍 |
| 编制完整度筛选器 | 列删掉后，它筛选的是页面上**已看不到的属性**——用户把行筛没了却看不出原因，故一并移除（用户已确认） |
| 操作列 | 「查看 / 更新」的全部去向已由**业务部门格与 ①②③ 格点击下钻**覆盖，操作列是第三份冗余入口；下钻抽屉内的运维动作（出具 / 复核确认 / 退回）不受影响 |

随之删除的死代码：`nextActionOf()`、`STAGE_SHORT`（均只被操作列消费）。

## 3. 「总预算费用」取数口径（用户二选一确认）

三个候选口径中用户选定 **「清单当前版本合计」**：

```
总预算费用(BU) = 清单当前版本费用合计 + 系统运维预算(计费模型年化)
                 ├─ 项目：Digital 已核定优先，未核定按业务预估（= annualPlanRow.projectAmount）
                 └─ 运维：按系统计费模型 12 个月求和 × 编制年增长系数（= annualPlanRow.opsAmount）
```

* 与页头「总项目费用（清单当前版本）」「系统运维预算」两张金额指标卡**同源**。
* **代价（已知情接受）**：未确认清单的 BU 会出现「② 列显示待核定、总预算费用列却已有数」——
  两者口径不同（② 只认已确认版本，本列含业务预估），页脚读法已显式说明这一差异。
* 未做下钻、不挂状态行：它是两个金额的和，不重复承载状态（克制原则）。
