# v0.7.1 · 部门预算消耗表：去进度条 + 去状态列

> **后续变更**：本文的「预算 / 消耗」两子列已在 **v0.7.2** 中并为单列
> （见 `docs/v0.7.2-department-table-merge-columns.md`），列宽由 958 收到 670。
> 本文关于分组表头、列宽 958 的记述保留为 v0.7.1 当时的快照。

> 变更范围：仅「预算管理 › 预算消耗 › 楼层二《部门预算消耗情况》」的表格。
> 楼层一三张卡、`consumptionBreakdown` 口径、`store.adjustProjectBudget`、「调整预算计划」抽屉分支一律未动。

## 1. 用户要求

> 部门预算列表上，不用显示消耗进度条，只用展示消耗百分比，给消耗百分比的数字用颜色标识预算健康度就好；
> 状态这一列 也不需要了

## 2. 旧版为什么该改

v0.7 的消耗格是「消耗金额 + 细进度条 + 已消耗 xx.x%」三级结构。一行 3 个维度 = **一行 6 根进度条并排**
（132px 宽的格里塞一根 100% 满宽的条，外加上下两行文字）。

| 问题 | 具体表现 |
|---|---|
| **信息密度倒挂** | 进度条只表达一个标量（消耗率），却占掉一格 4px 高的独立行；而它表达的信息 `xx.x%` 就写在它下面一行 —— 同一件事说了两遍 |
| **色噪声** | 一行里 6 根彩色横条，饱和度高的红/橙条会盖过真正需要看的数字；「哪一格吃紧」要靠数颜色才能定位 |
| **重复列** | 「状态」列给的是**整体维度**的 `档位 · 率`（`预警 · 96.5%`），而「整体预算及消耗 → 消耗」格里已经有同一个 `96.5%` 和同一个档位色 —— 一列是另一列的副本 |
| **宽度浪费** | 156 + 120 = 276px 用于表达 3 个数字；表格总宽 1186px，1366 笔记本要横向滚动 |

## 3. 改后的消耗格

```
        ┌──────────────── 120px ────────────────┐
                               2,511.2            ← 消耗金额，14px/500，tabular-nums
                        已消耗  56.6%             ← 「已消耗」11px 三级灰 + 消耗率 13px/600 着档位色
```

- **百分比着档位色**，色值取自 `theme.levelColor()`，与楼层一 `PoolLevelTag`、进度条**同源**：

| 档位 | 阈值（`calc.poolLevel`） | 色值 | 白底对比度 |
|---|---|---|---|
| 正常 `ok` | < 70% | `#2E7D32` 绿 | 5.13:1 ✓ AA |
| 关注 `watch` | 70% ~ 90% | `#005BAA` 蓝 | 6.73:1 ✓ AA |
| 预警 `warn` | 90% ~ 100% | `#C77700` 橙 | 3.44:1 ✗ AA |
| 已透支 `over` | ≥ 100% | `#C0392B` 红 | 5.44:1 ✓ AA |

> **预警橙 3.44:1 未达 WCAG AA（正文 4.5:1）**。这是沿用进度条原有的 `strokeColor`，本次没有改色值 ——
> 若你在意可读性（尤其投屏 / 打印），把 `main.jsx` 的 `colorWarning` 从 `#C77700` 压到 `#A85F00`（约 4.95:1）即可全绿，
> 但会同步影响全站所有 warning 元素。**取没有替你改色**。

**着色是逐维度独立判定的**，这正是「状态」列可以拿掉的前提 —— 同一行里三个维度可以不同色，实测：

```
部门               整体                项目                运维
客户服务 D-SVC     110.3% 红           294.8% 红            58.0% 绿
会员与客流 D-CRM    62.3% 绿            73.9% 蓝（关注）       55.3% 绿   ← 整体正常、项目侧进「关注」
市场营销 D-MKT      60.3% 绿           106.5% 红            55.3% 绿   ← 整体正常、项目侧已击穿
零售运营 D-RETAIL   54.7% 绿            53.6% 绿            55.3% 绿
```

「整行一个档位」的旧「状态」列**表达不了** `D-CRM` / `D-MKT` 这两行，
而这恰好是 v0.7 把项目 / 运维拆开看之后暴露出来的最要紧的结构性问题。

## 4. 合计行同步去进度条

合计行原来靠一个绿色 `Tag` + 一行文字；现在与表体同构：`已消耗 2,511.2 · 56.6%`，三个维度的率同样着色
（56.6% 绿 / 58.1% 绿 / 55.7% 绿）。**合计行与表格体继续同源**（都求和自 `allRows`），
所以「合计看着正常、某个维度已透支」在合计行也读得出来。

「N 个透支 · N 个预警」原来挂在状态列的合计格里，现迁到楼层二标题行右上角：
`透支 1 个 · 预警 0 个 · 置顶排序`。

## 5. 列宽与宽度收益

| 列 | v0.7 | v0.7.1 | 依据 |
|---|---:|---:|---|
| 业务部门 | 116 | 116 | 不动 |
| 消费格（×3 组，每组 预算 + 消耗） | 108 + 156 | **108 + 120** | 去掉进度条后格内最长内容 = `2,511.2`（≈64px）+ `已消耗 294.8%`（≈78px）→ 120 有 40px 余量 |
| 状态 | 120 | **—** | 整列删除 |
| 操作 | 158 | 158 | 两个 link 按钮（查账 / 调整预算计划）不动 |
| **合计** | **1186** | **958** | **−228px（−19.2%）** |

`scroll.x: 1186 → 958`。以 1280 屏（减去 224px 侧栏 + 48px 内边距，可用约 976px）计：
v0.7 必然横向滚动，v0.7.1 **不再触发**。

## 6. 一个没动的东西：筛选项「消耗档位」

状态列删了，但筛选栏里的「消耗档位」下拉（全部 / 正常 / 关注 / 预警 / 已透支）**保留**。
理由：颜色只在视野内可见，而筛选是**定位**手段 —— 8 个部门能一屏看完，但部门数量增长后
「只看已透支」是刚需；且它筛的是**整体维度**的档位，语义与已删的状态列一致，不引入新口径。
若你认为多余，删掉 `fields` 里的 `level` 一项即可（连带 `rows` 的 `f.level` 分支）。

## 9. 未验证

**真机视觉核对未做** —— 本机无头 Chrome 仍启动即退（`--dump-dom` / `--screenshot` 均无产出），

但以下三点只有你在浏览器里能判断：

1. `已消耗 294.8%` 这类三位数百分比在 120px 格里是否与金额挤在一起（实测文本宽约 78px，理论余量 42px）；

3. 红的 `#C0392B` 与相邻绿的 `#2E7D32` 并排时是否刺眼。
