# v0.3 预算管理板块 IA 变更记录

> 本文替代 `DESIGN.md` §导航结构 与 `docs/v0.2-requirement-brief.md` 中「预算管理」部分的模块划分。
> v0.2 其余内容（设计系统、计费与交付板块）不受影响。

## 一、变更动因（业务口径修订）

业务部门年度 Digital 预算的构成被明确为三部分，此前的模块划分与实际口径不匹配：

| 组成 | 产出方 | 复核确认方 |
| --- | --- | --- |
| ① 业务规划 BP 文档 | 业务部门 | — |
| ② 数字化需求清单及各条费用预估 | 业务部门 | Digital 部门 |
| ③ 支撑该部门的系统运维预估费用 | Digital 部门 | 业务部门 |

由此产生两个结构性矛盾：BP 与需求清单同属「次年编制产物」却被拆成两个视图，用户的编制动作被割裂；运维预估费用没有任何承载视图。

## 二、模块映射

### 二级视图（预算管理板块）

| v0.2 | v0.3 | 说明 |
| --- | --- | --- |
| 业务规划 BP | **年度预算计划**（合并） | 与「年度需求清单」融合为同一张纵向主表 |
| 年度需求清单 | **年度预算计划**（合并） | 同上 |
| 预算池总览 | **预算消耗**（更名） | 展示口径扩张：总包 → 项目费用预算 / 系统运维费用预算 / 截至当月消耗进度 |
| Digital 整合规划 | **已下线** | 整合口径并入「年度预算计划」的费用汇总 |
| 部门预算池 | **已下线** | 「查账」由账单模块承接；「调节额度」收口到「预算消耗」行内 |

旧 hash 不静默失败：`#/budget/{pool|bp|demand|plan|deptpool}` 一次性提示后重定向到承接视图（`src/App.jsx` 的 `LEGACY_VIEWS`）。

### 《年度预算计划》页面主体

一张纵向主表，行为 BU，列为四个编制项（均可点击下钻）+ 编制完整度 + 操作：

| 列 | 单元格内容 | 下钻抽屉 |
| --- | --- | --- |
| ① 年度 BP 提交及更新 | 状态胶囊 · 版本与附件数 · 最近更新时间 | BP 详情 + 提交 / 归档 + 操作记录 |
| ② 需求清单提交及更新 | 条数 · 预估金额 · 状态（待复核 N / 已定稿） | 清单明细（每条可看溯源链）+ 提交 / Digital 复核确认 + 操作记录 |
| ③ 总项目费用提交及更新 | 金额（= 清单各条预估之和） | 费用构成（按优先级）+ 项目费用预算差额预警 + 操作记录 |
| ④ 系统运维预算提交及更新 | 金额（Digital 按计费模型出具） | 系统清单与年化预估 + 业务复核确认 / 退回 + 操作记录 |

辅助入口：**全部操作记录**（全 BU 留痕）、**导出计划**、行内 **查看 / 更新**（更新直达下一步待办动作）。

### 《预算消耗》页面主体

预算费用总包 = 项目费用预算 + 系统运维费用预算；消耗进度按「截至当月」口径（已核销按项目 / 运维分列 + 已承诺）。
行内操作：**查账**（跳转 `billing/monthly/{部门代码}`，由账单模块给出该 BU 全年度账单流水与逐笔明细）、**调节额度**。

## 三、数据与计算层新增

| 位置 | 新增 | 说明 |
| --- | --- | --- |
| `data/mock.js` | `OPS_PLANS` | 运维预算计划的编制元数据（版本 / 状态 / 双方责任人 / 出具与确认时间），金额不落库 |
| `data/mock.js` | `PLAN_ACTIVITIES` | 编制期操作留痕（部门 · 编制项 · 动作 · 操作人 · 角色 · 时间 · 说明） |
| `data/mock.js` | `DEPARTMENTS[].opsGrowth` | FY2027 运维业务量增长系数；执行年度恒为 1，不影响当年账单 |
| `data/mock.js` | 移除 `DIGITAL_PLAN` | 随「Digital 整合规划」下线 |
| `domain/calc.js` | `opsPlanBySystem` / `opsAnnualEstimate` | 按运维计费模型对 12 个自然月年化，再乘增长系数 |
| `domain/calc.js` | `budgetComposition` | 总包 = 项目费用预算 + 系统运维费用预算 |
| `domain/calc.js` | `consumptionUpTo` | 截止当月的消耗进度（项目 / 运维分列 + 已承诺） |
| `domain/calc.js` | `annualPlanRow` / `annualPlanRows` | 单个 BU 四个编制项的状态、金额与最近一次操作 |
| `store.jsx` | `planAction` | 编制项统一动作入口：落 planActivity + 同步业务对象状态 + 写审计日志 |

金额一律由 `domain/calc.js` 推导，未在数据层硬编码 —— 沿用「钱怎么算只有一个真相来源」原则。

## 四、回归验证

- `npm run build`：通过。
- `node tests/smoke.cjs`：61/61 通过（含 v0.3 定向断言：四编制项锚点、查账跳转、旧 hash 重定向、全站已无「深钻 / Digital 整合规划 / 部门预算池」）。
